# Принтер этикеток `3B-350B` — 58×38 мм

Схема для текущей сети:

```text
MSB / print-agent                 компьютер nick                  USB-принтер
192.168.8.81  ── CUPS :631 ──▶   192.168.5.238  ── USB ──▶       3B-350B
```

Print-agent продолжает работать на сервере MSB. Второй агент на компьютере
`nick-MS-7758` не нужен: для задания этикетки агент вызывает удалённую очередь
CUPS `3B-350B` на `192.168.5.238:631`. Основной A4-принтер продолжает работать
по прежней конфигурации.

Этикетка содержит:

- номер ремонта;
- имя заказчика;
- телефон заказчика;
- QR на закрытую карточку `/repairs/{id}` для мастера.

Если мастер ещё не авторизован, после входа MSB вернёт его в отсканированную
карточку. Обычный клиентский публичный QR `/r/{token}` здесь не используется.

---

## 1. Проверка принтера на `192.168.5.238`

На компьютере `nick-MS-7758`:

```bash
hostname -I
lpstat -p
lpstat -v 3B-350B
lpoptions -p 3B-350B -l | grep -Ei 'PageSize|media' || true
```

Ожидается очередь:

```text
принтер 3B-350B свободен
```

Сначала убедитесь, что локальная печать работает:

```bash
printf 'MSB local test\n' | lp -d 3B-350B
lpstat -o 3B-350B
```

Если локальная печать не работает, сначала исправьте драйвер/очередь на этом
компьютере. Настройки MSB не могут исправить неисправную локальную CUPS-очередь.

---

## 2. Разрешение удалённой печати в CUPS

На `192.168.5.238`:

```bash
sudo apt update
sudo apt install -y cups cups-client ufw
sudo systemctl enable --now cups

# Расшарить принтеры и принимать подключения не только с localhost.
sudo cupsctl --share-printers --remote-any
sudo lpadmin -p 3B-350B -o printer-is-shared=true
sudo systemctl restart cups

sudo ss -ltnp | grep ':631'
```

После `cupsctl` порт `631` должен слушать сетевой интерфейс, а не только
`127.0.0.1`.

`--remote-any` расширяет доступ на уровне CUPS, поэтому на уровне firewall
разрешите порт **только серверу MSB**. Если UFW активен:

```bash
sudo ufw status verbose
sudo ufw allow from 192.168.8.81 to any port 631 proto tcp \
  comment 'MSB server to label printer'
sudo ufw status numbered
```

Правило ограничивает доступ только при политике UFW `deny (incoming)`. Если UFW
показывает `inactive` или входящая политика — `allow`, добавленное правило само
по себе ничего не фильтрует. Согласуйте включение/политику firewall с
администратором этого компьютера (сначала разрешите используемый доступ SSH)
либо задайте такое же ограничение источника в уже используемом firewall/VLAN.
Не оставляйте `--remote-any` без сетевого
ограничения, не создавайте широкое правило `allow 631/tcp` и не пробрасывайте
порт `631` в интернет.

> Сервер и компьютер принтера находятся в разных подсетях (`192.168.8.0/24` и
> `192.168.5.0/24`). Между ними должен существовать маршрут. Если ping работает,
> а TCP/631 нет, проверяйте firewall и настройки CUPS. Если ping не работает,
> маршрут/VLAN должен настроить администратор сети.

## 3. Проверка с сервера MSB

На `192.168.8.81`:

```bash
sudo apt install -y cups-client netcat-openbsd

ip route get 192.168.5.238
ping -c 3 192.168.5.238
nc -zv 192.168.5.238 631
lpstat -h 192.168.5.238:631 -p 3B-350B
```

Затем отправьте простой тест из сервера в удалённую очередь:

```bash
printf 'MSB remote CUPS test\n' | \
  lp -h 192.168.5.238:631 -d 3B-350B
```

Если драйвер уже поддерживает именованный размер, можно проверить его отдельно:

```bash
printf 'MSB 58x38 test\n' | \
  lp -h 192.168.5.238:631 -d 3B-350B \
  -o media=Custom.58x38mm
```

Если второй вариант возвращает ошибку про media, это не проблема сети. Узнайте
точное имя размера командой `lpoptions -p 3B-350B -l` на компьютере принтера или
оставьте поле Media option в MSB пустым и задайте 58×38 как размер очереди по
умолчанию.

## 4. Обновление MSB

На сервере после получения новой версии кода:

```bash
cd /home/windowrepair-ae/msb
git pull --ff-only
sudo bash deploy/update.sh
sudo systemctl --no-pager --full status msb-api msb-web msb-print-agent
```

Для удалённой CUPS-печати в systemd не нужны новые переменные. Существующий
`MSB_PRINT_CMD` основного A4-принтера можно оставить: задания с режимом
`cups_remote` обходят эту команду и используют адрес/очередь из настроек
этикетки.

---

## 5. Настройка в интерфейсе MSB

Откройте:

```text
Админ → Принтеры → Принтер этикеток 58×38 мм
```

Значения:

| Поле | Значение |
|---|---|
| IP компьютера с CUPS | `192.168.5.238` |
| Порт CUPS | `631` |
| Имя очереди | `3B-350B` |
| Media option | `Custom.58x38mm` или пусто, если драйвер его не знает |

Формат PDF `58×38 мм` зафиксирован приложением и в интерфейсе не изменяется.

Нажмите:

1. **Сохранить этикетку**;
2. **Тест 58×38**;
3. проверьте статус задания в блоке «Последние задания».

PDF создаётся сразу с физическим размером страницы 58×38 мм. Масштабирование на
A4 не используется.

## 6. Печать после новой приёмки

После создания ремонта появляется экран «Техника принята». На нём есть отдельная
кнопка:

```text
🏷️ Печатать этикетку 58×38
```

Кнопка создаёт только задание этикетки. Бланк A4 печатается отдельной кнопкой.
Повторно напечатать этикетку можно также из карточки ремонта.

QR ведёт на адрес вида:

```text
http://192.168.8.81:3030/repairs/UUID-РЕМОНТА
```

Поэтому в `/home/windowrepair-ae/msb/.env` должно быть:

```ini
PUBLIC_BASE_URL=http://192.168.8.81:3030
```

Телефон мастера должен видеть `192.168.8.81:3030` по сети. Мастер должен быть
назначен на ремонт — действующие правила MSB не дают мастеру читать чужие
ремонты.

## 7. Диагностика

### Задание осталось в очереди

```bash
sudo systemctl status msb-print-agent
sudo journalctl -u msb-print-agent -n 150 --no-pager
```

### `Connection refused` / timeout

На сервере:

```bash
nc -zv 192.168.5.238 631
```

На компьютере принтера:

```bash
sudo systemctl status cups
sudo ss -ltnp | grep ':631'
sudo ufw status numbered
```

### CUPS отвечает `Forbidden`

Повторно проверьте sharing:

```bash
sudo cupsctl --share-printers --remote-any
sudo lpadmin -p 3B-350B -o printer-is-shared=true
sudo systemctl restart cups
```

### Ошибка `media=Custom.58x38mm`

Посмотрите поддерживаемые варианты:

```bash
lpoptions -p 3B-350B -l | grep -Ei 'PageSize|media'
```

Укажите точное значение в админке либо очистите Media option и настройте размер
58×38 мм по умолчанию в драйвере CUPS.

### Этикетка повёрнута или обрезана

1. убедитесь, что рулон/этикетка действительно 58×38 мм;
2. проверьте в CUPS ориентацию и физический размер страницы;
3. не включайте дополнительное «fit to A4»;
4. распечатайте скачанный PDF — его MediaBox должен быть ровно 58×38 мм.

### QR открывает неправильный IP

```bash
grep '^PUBLIC_BASE_URL=' /home/windowrepair-ae/msb/.env
sudo systemctl restart msb-api
```

Должно быть `http://192.168.8.81:3030`.
