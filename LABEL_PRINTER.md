# Принтер этикеток `label58` — 58×38 мм

Схема для текущей сети:

```text
MSB / print-agent                CUPS на сервере MSB              принтер этикеток
192.168.8.81  ── lp -d label58 ──▶  очередь label58  ── socket ──▶  192.168.5.105:9100
```

Print-agent работает на сервере MSB и печатает в **локальную** очередь CUPS
`label58`. Адрес принтера знает сам CUPS — MSB он не нужен, поэтому в
настройках указывается только имя очереди: ни IP, ни порт.

> **Порт 9100 — это raw-порт принтера** (JetDirect/AppSocket), а не порт CUPS;
> CUPS слушает 631. Указывать 9100 в настройках MSB не нужно: агент не
> обращается к принтеру напрямую, он отдаёт PDF в CUPS, а драйвер очереди уже
> готовит данные для принтера. Попытка отправить PDF напрямую в 9100 не
> сработает — принтер ждёт свой язык разметки, а не PDF.

При приёмке печатаются **две** этикетки 58×38 (единым проходом — два задания
в очереди на ту же очередь `label58`):

1. **Этикетка на технику** — содержит:

   - номер ремонта;
   - имя и телефон заказчика;
   - отмеченную при приёмке комплектацию;
   - отмеченные пункты «Внешний вид / дефекты», включая значение «Другое»;
   - QR на закрытую карточку `/repairs/{id}` для мастера;
   - подпись `MERYOSAB electronics` внизу.

2. **Этикетка клиенту** — номер ремонта, крупный QR на публичную страницу
   `/r/{token}` (без логина), где клиент видит статус ремонта, условия
   хранения и юридическую информацию; строка про срок хранения
   (`storage_months` из настроек) прямо на этикетке.

Повторная печать любой из двух — из карточки ремонта («🏷 Этикетка» /
«🏷 Клиенту (QR)») или из меню ⚡ в списке «Все ремонты».

Если мастер ещё не авторизован, после входа MSB вернёт его в отсканированную
карточку. Обычный клиентский публичный QR `/r/{token}` здесь не используется.

---

## 1. Проверка очереди на сервере MSB

На сервере `192.168.8.81`:

```bash
lpstat -p                 # список очередей — label58 должна быть в списке
lpstat -v label58         # устройство: socket://192.168.5.105:9100
```

Ожидается:

```text
устройство для label58: socket://192.168.5.105:9100
```

Проверьте, что локальная печать работает:

```bash
printf 'MSB local test\n' | lp -d label58
lpstat -o label58
```

Если локальная печать не работает, сначала исправьте очередь на сервере —
настройки MSB не могут починить неисправную очередь CUPS.

Если очереди ещё нет, её создаёт администратор сервера, например:

```bash
sudo lpadmin -p label58 -E \
  -v socket://192.168.5.105:9100 \
  -m everywhere            # либо PPD конкретной модели
lpoptions -p label58 -l | grep -Ei 'PageSize|media'
```

Точное имя размера страницы из последней команды — это значение для поля
**Media option** в MSB (обычно `Custom.58x38mm`).

## 2. Настройка в интерфейсе MSB

Откройте:

```text
Админ → Принтеры → Принтер этикеток 58×38 мм (CUPS)
```

Значения:

| Поле | Значение |
|---|---|
| Очередь CUPS | **На этом сервере (достаточно имени очереди)** |
| Имя очереди | `label58` |
| IP компьютера с CUPS | пусто — не используется в локальном режиме |
| Порт CUPS | пусто — не используется в локальном режиме |
| Media option | `Custom.58x38mm` или пусто, если драйвер его не знает |

Формат PDF `58×38 мм` зафиксирован приложением и в интерфейсе не изменяется.

Нажмите:

1. **Сохранить этикетки**;
2. **Тестовая этикетка**;
3. проверьте статус задания в блоке «Последние задания».

Агент выполнит:

```bash
lp -d label58 -o media=Custom.58x38mm <файл.pdf>
```

Задания этикеток **не используют** `MSB_PRINT_CMD` основного A4-принтера —
иначе этикетка уехала бы на `EPSON_L3250`.

### Если CUPS на другом компьютере

Второй режим — **На другом компьютере (нужен IP и порт 631)**. Тогда указываются
IP машины с CUPS, порт `631` и имя расшаренной очереди; агент печатает через
`lp -h <ip>:631 -d <очередь>`. Порт 9100 в этом режиме тоже не используется.

## 3. Печать после новой приёмки

После создания ремонта появляется экран «Техника принята». На нём есть отдельная
кнопка:

```text
🏷️ Печатать этикетку 58×38
```

Кнопка создаёт только задание этикетки. Бланк A4 печатается отдельной кнопкой.
Повторно напечатать этикетку можно также из карточки ремонта.

QR ведёт на адрес вида:

```text
http://192.168.8.81:8085/repairs/UUID-РЕМОНТА
```

Поэтому в `/home/windowrepair-ae/msb/.env` должно быть:

```ini
PUBLIC_BASE_URL=http://192.168.8.81:8085
```

Телефон мастера должен видеть `192.168.8.81:8085` по сети. Мастер должен быть
назначен на ремонт — действующие правила MSB не дают мастеру читать чужие
ремонты.

## 4. Диагностика

### Задание осталось в очереди

```bash
sudo systemctl status msb-print-agent
sudo journalctl -u msb-print-agent -n 150 --no-pager
```

### `lp: unable to print` / очередь не найдена

Агент пишет в лог список доступных очередей. Сверьте имя:

```bash
lpstat -p
lpstat -v label58
```

Имя в MSB должно совпадать с именем очереди в CUPS буквально, с учётом регистра.

### Принтер не отвечает

```bash
ping -c 3 192.168.5.105
nc -zv 192.168.5.105 9100
```

Сервер и принтер находятся в разных подсетях (`192.168.8.0/24` и
`192.168.5.0/24`) — между ними должен быть маршрут. Если ping есть, а TCP/9100
нет, проверяйте firewall на стороне принтера.

### Ошибка `media=Custom.58x38mm`

Посмотрите поддерживаемые варианты:

```bash
lpoptions -p label58 -l | grep -Ei 'PageSize|media'
```

Укажите точное значение в админке либо очистите Media option и настройте размер
58×38 мм по умолчанию в драйвере CUPS.

### Этикетка повёрнута или обрезана

1. убедитесь, что рулон/этикетка действительно 58×38 мм;
2. проверьте в CUPS ориентацию и физический размер страницы;
3. не включайте дополнительное «fit to A4»;
4. распечатайте скачанный PDF — его MediaBox должен быть ровно 58×38 мм.

### QR открывает неправильный IP

```bash
grep '^PUBLIC_BASE_URL=' /home/windowrepair-ae/msb/.env
sudo systemctl restart msb-api
```

Должно быть `http://192.168.8.81:8085`.
